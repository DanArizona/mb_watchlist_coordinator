# Daily Hot operating qualification

Run `63_verify_daily_hot_operating.cmd` in sea-green after extracting this ZIP
into its own output directory. Allow approximately two minutes and about 1 GB
of free temporary/output space. Supply the final JSON and actual CMD prompt
return. This packet has no installation, start, resume or activation command.

All data, credentials and SDK behavior in verification are synthetic. Network
is denied. Production source, journals, settings, credentials, processes and
Uni/Focus/Health are untouched. Proposed policy values remain unadopted and
production Hot remains disabled. No password is requested.

The new independent outer owner gates and owns its controller process tree,
uses the original progress/credential/hold/cleanup/report limits, and saves
cleanup before starting a separately owned reporter. Parent loss, stale parent
evidence, bound stop requests, unrelated process survival, forced cleanup,
bounded reporting and a stopped native journal/replay are checked. A detected
stop is latched even if parent evidence subsequently recovers.

Daily history verification compares every scoped persisted raw event, header,
observation and skip value in SQLite against a process-local in-memory mirror
on every read. Added rows are fully validated and checked against the native
response/ACK contract. Edits, deletion, extra old observations, unknown
headers, schema changes and file replacement cannot be hidden by an unchanged
head, timestamp or row count. Membership reuse rereads all raw header/member
values within a consistent read transaction. No persistent trust cache exists.
The ordinary standalone collector and store remain separate reference paths.

The representative capacity proof seeds 9,358 Hot outcomes plus full Uni/Focus
background data, then executes two native acquisitions using an advancing
elapsed clock. Opening size is 600 Uni/40 Focus, plus one admitted NVDA;
directory size includes 7,000 additional records. Final storage has 780 Uni,
1,560 Focus and 9,360 Hot acquisitions, 542,099 observations. An actual cold
owned process uses synthetic authentication and must finish first native work
within the original three-second gate. The full journal must pass audit and
two fresh replays. This measures representative synthetic history processing;
it does not execute 9,360 provider calls, a full live session, or qualify a
provider. All original limits remain unchanged.

`runs` holds results and closed forensic evidence. Capacity SQLite work runs
in a private temporary directory, then copies closed files to the run folder.
Those copies retain their original path-bound identities and must not be
adopted as live roots. Failed or interrupted runs stay evidence. Re-extracting
over an existing packet is unnecessary; run the CMD only once for this packet.
Source inventory is checked before imports and after verification.

Read-only operator commands are available as `python -I -B run.py review ...`,
`outer-status --outer-root PATH` and `hot-status --state-root PATH`.
`stop --outer-root PATH` submits a nonce/configuration-bound cooperative stop
only for that existing owned invocation. It discovers, adopts or restarts no
process. Review requires saved `--opening-proposal`, `--focus-proposal`,
`--journal`, `--catalog-root`, `--state-root` and `--ecfg` arguments; it creates
no runtime state, prompts for no password, and makes no provider request.

This new source pair is a fresh-session candidate. It must not be substituted
into an older daily state or mixed with the accepted command-62 native source.
Windows acceptance, provider/deployment/rollback review and explicit settings
and activation approval remain before any controlled live Hot operation.
Manual membership controls and read-only Overlay integration follow closely.
